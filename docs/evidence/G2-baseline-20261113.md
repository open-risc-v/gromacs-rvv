# gromacs G2：native A/B 与 riscv64 交叉基线（2026-11-13）

- 上游：`gromacs/gromacs` @ `5a4f586`
- 构建：cmake，`GMX_FFT_LIBRARY=fftpack`（内置）、`GMX_MPI=OFF`、`GMX_THREAD_MPI=OFF`、
  `GMX_GPU=OFF`、`GMX_SIMD=None`、`GMX_DOUBLE=OFF`、`BUILD_TESTING=OFF`
- 探针：`gmx editconf`，把固定的 8 原子 `.gro` 加 5nm 盒并居中

| 项 | native | riscv64 (rv64gc) |
|---|---|---|
| 输出字节 | 417 | 417 |
| 结构哈希 | `8209a17e6a3c3329` | 同左 |

## 三个口径选择（都是为"两侧走同一份代码"

1. **`GMX_SIMD=None`**：aarch64 默认走 NEON、riscv 默认走标量参考实现，两者数值不保证逐位相同。
   基线阶段把 SIMD 全关，先证明"同一份标量代码两侧一致"；SIMD/RVV 化的差异留给 G3 差分。
2. **`GMX_FFT_LIBRARY=fftpack`（内置）**：交叉环境里没有 riscv 的 fftw3 前缀。
   下一步可换成 `-DGMX_FFT_LIBRARY=fftw3` 并挂 `fftw-rvv` 编好的前缀——那时才需要保证
   FFT 数值一致（估计要放容差，不能要求逐位）。
3. **探针选 `editconf` 不选 `mdrun`**：`mdrun` 需要 `.tpr` + 力场（`grompp` 还要 `.mdp/.top`
   和整套力场数据），基线阶段代价过高；`editconf` 走的是真实的上游路径（坐标/拓扑解析、
   盒子与居中计算），输出是纯文本结构文件，可逐字节比较。

## 踩到的坑

- **`BIN` 是 cmake 构建目录，不是上游前缀**：探针脚本里要取 `${BIN}/pkg/prefix`，
  第一次写成 `$BIN` 直接报了"cannot execute binary file"。
- **`gmx` 需要 `GMXLIB` 指到 `<prefix>/share/gromacs/top`**，否则会去默认路径找数据目录。
